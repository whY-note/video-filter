# Video Filter 设计

## 布局

页面标题为 Video Filter。左侧为三路视频，头部相机在上方占满宽度，下方左右分别为左相机和右相机，视频保持比例并标注相机名称。三路视频下方只有一组播放控件：播放／暂停、共用进度条、当前时间／总时长，以及 1×、2×、4×、8× 倍速。

左侧不显示任务／轨迹标题和底部播放状态文字，视频区贴合外框边缘，并占满播放控制栏以外的空间。播放状态仅通过无障碍实时提示提供，不占用界面空间。

视频区默认上下高度为 2:1，下方左右宽度为 1:1（扣除分界线）。两条分界线通过 Pointer Events 和指针捕获支持鼠标及触摸拖动，直接调整 Grid 的比例，视频用 `object-fit: contain` 自然缩放，不重新加载视频或改变播放状态。各区域至少保留所在轴 10% 的空间，支持方向键调整、双击恢复默认。比例在切换轨迹和窗口缩放时保留，刷新页面恢复默认。

右侧保留任务输入、Requirement、筛选进度、达标进度，以及接受／拒绝按钮。筛选进度为已处理轨迹数／总轨迹数，达标进度为已接受轨迹数／目标数量。拒绝只记录状态，不删除文件；接受和拒绝均切换下一条轨迹。

## 轨迹发现

从 `videos/<任务名字>/` 的直接子目录读取 `traj_<数字>_videos`，按数字排序。每个目录为一条筛选记录。

`videos/<任务名字>` 支持指向外部目录的绝对路径或相对路径软链接。先校验任务路径是 `videos/` 的直接子项，再解析真实目录；轨迹发现、视频读取和进度读写均以该真实目录为边界，拒绝任务内部指向边界之外的软链接。任务 YAML 仍从 `Task_Requirement/` 读取，进度保存在软链接目标目录。

相机依次匹配 `front_camera` / `head_camera`、`left_wrist_camera` / `left_camera`、`right_wrist_camera` / `right_camera`；优先前一个名称，再按 `.mp4`、`.webm`、`.ogg`、`.ogv` 顺序匹配格式。文件名匹配不区分大小写。缺失相机显示占位，没有任何可识别视频的目录跳过。

任务配置继续读取 `Task_Requirement/<任务名字>.yaml` 的 `requirements` 和 `target_count`。目标数量必须为正整数，且不能超过可用轨迹数量。

## 共用播放器

通过视频 URL 直接加载，服务端支持 Range 请求，允许浏览器按需读取和定位。视频均静音，不显示原生独立控制条。

等待所有存在的视频取得元数据或确认失败后，使用可播放视频中的最短时长作为共用时间轴。三路自动播放、共同循环；第一路可播放视频作为时钟，其他视频偏差超过 0.2 秒时校正。倍速统一设置，切换轨迹时保留。

拖动进度条时暂停并同步定位，结束后恢复之前的播放状态；缓冲时共同暂停等待。自动播放失败则提示点击播放；单路失败显示占位，不影响其余视频和筛选操作。切换轨迹时释放旧视频资源，避免后台继续播放。

## 接口与存储

- `POST /api/load-task`：输入 `task_name`，返回描述、`total_trajectories`、`target_count` 和已处理／接受数量。
- `GET /api/current-trajectory`：返回 `trajectory`、`videos`（`head`、`left`、`right` 相对路径或 `null`）、`current_index` 和 `total`。完成时返回 `trajectory: null`、`videos: null` 和完成提示。
- `GET /api/video/<path:video_path>`：只允许读取当前任务中已发现的视频，支持 Range 请求，限制路径及符号链接越界。前端附加 `task_name` 查询参数区分不同任务的同名视频，避免缓存混用；任务不匹配返回 409。
- `POST /api/mark-accept`、`POST /api/mark-reject`：输入 `trajectory`，返回进度数量。同结果重复提交不重复计数，已处理轨迹的相反结果返回 409。

进度保存于 `videos/<任务名字>/progress.json`，`processed` 和 `accepted` 数组记录轨迹目录名。加载时去重并忽略已不存在的轨迹，写入时用临时文件替换；保存失败不更新内存中的进度。旧图片接口和进度不再使用。

应用沿用单进程共享当前任务的模式；服务端用锁串行处理任务加载和标记，前端在请求期间禁用重复提交。
